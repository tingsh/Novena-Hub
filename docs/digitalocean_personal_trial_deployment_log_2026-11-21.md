## Setup and verification timeline

1. **Host access and base services.** The owner created a dedicated DigitalOcean SSH key, configured the `shouheng` sudo account, hardened SSH, installed Docker Engine/Compose, and set up Nginx and Certbot. The Droplet was created without paid automated backups to control costs for this personal trial. Do not treat this as an acceptable customer-data recovery arrangement.
2. **DNS, firewall, and certificates.** The owner created the four Cloudflare DNS names and the DigitalOcean firewall. Nginx handled the HTTP certificate challenge for both the web and MQTT names; Mosquitto uses the separate MQTT certificate on port 8883. Both issuance and simulated renewal passed.
3. **Production environment.** The private `deploy/env/production.env` was created on the Droplet with mode 600. Generated, distinct production values cover Django, PostgreSQL, health check, MQTT admin, Gateway claim/activation, and remote-control signing. Do not reuse the local development PostgreSQL password. Real SES credentials were deliberately left unconfigured, `EMAIL_BACKEND` uses console output for the trial, and WhatsApp remains mock. The environment and Compose configuration were checked without printing secrets.
4. **MQTT certificate access.** Certbot's MQTT private key was root-only (`600 root:root`), while the broker runs as UID/GID 1883. [PR #35](https://github.com/tingsh/Novena-Hub/pull/35) added `deploy/mosquitto/sync_tls_cert.sh` and a Certbot deployment hook. The script copies the key to an ignored, restricted broker directory as `640 root:1883`; the certificate chain is readable. A disposable container running as `1883:1883` proved it could read both files. The original Certbot key remains root-only.
5. **Broker identity and permissions.** PR #35 added `deploy/mosquitto/init_dynsec.py`, which initialized the live Dynamic Security state from the private environment without printing credentials. It created an admin identity and an empty Gateway role with deny-by-default ACLs. Compose now runs Mosquitto explicitly as `1883:1883`, and the broker data directory remains traversable by the repository owner. The initializer must not be rerun over the live state.
6. **Broker startup bug.** The first Mosquitto start exited with code 31 because the moving `eclipse-mosquitto:2` image resolved to 2.1.4, which rejects loading Dynamic Security twice. PR #35 changed the config to `plugin_load` once and `plugin_use` on admin and public TLS listeners, and pinned `eclipse-mosquitto:2.1.4-alpine`. After recreation, Mosquitto was healthy. External TLS verification passed and anonymous MQTT access was denied.
7. **Image build safety.** Before the first app build, PR #35 expanded `.dockerignore` so `production.env`, copied MQTT keys, Dynamic Security state, private media, backups, and `.git` are excluded from both Docker build stages. The initial app build completed for web, worker, Beat, and consumer. No live secret file was intentionally copied into those images.
8. **Database and Django.** The fresh PostgreSQL container became healthy. Django migrations completed through `web.0002_patch_djstripe_column`. A first `manage.py check` showed three deprecated django-allauth settings plus a Google SDK warning. The three old allauth settings were removed because their replacements already existed; local Django checks and eight focused signup/user tests passed. The Droplet rebuilt all four images in about 24 seconds with cache, and a new `manage.py check` had no allauth warnings. The Google warning remains. The dj-stripe `I001` message about missing database API keys is informational for this unpaid trial.
9. **Timescale and static files.** `verify_timescale` confirmed `telemetry_telemetrydata` is a hypertable. `scripts/database/verify_timescale_policies.sql` ran in a read-only transaction and ended with its required `PASS`. First `collectstatic` failed at `/code/static_root/marketing` because the host directory belonged to UID/GID 1000 while Django runs as 999. The owner assigned group 999 and set directory modes: `static_root` and `media` `2775`, `private_media` `2770`. The retry copied 313 static files. The deployment and readiness guides now include the group-permission step.
10. **Readiness inventory.** All checks were green except SES failure, Stripe test-mode warning, and missing Sentry warning. No change was made to weaken the readiness gate for the trial. The owner chose to defer Sentry while testing alone, and to defer automated backups to save cost.
11. **First full-stack startup.** The owner ran `sudo docker compose -f docker-compose.prod.yml up -d`; all seven services started. `compose ps` showed web, worker, Beat, and consumer Up; PostgreSQL, Redis, and Mosquitto remained healthy. Web startup completed, Celery scheduled and executed tasks, and the MQTT consumer connected and subscribed. External HTTPS checks returned app/www HTTP 200, root HTTP 301 to www, and certificate verification result 0. This proves basic public routing, not authenticated user or Gateway flows.
