## Defects fixed in this audit

1. **Misleading trend mathematics.** Command Center added every temperature sample in an hour. The cold-room chart exceeded 300 °C while the live reading was about 2–3 °C. It now plots one selected device's hourly numeric average, leaves missing periods blank, labels the device and aggregation, and shows site-local times and a readable `°C` unit. A cumulative `energy` key uses the last reading in each hour and is labelled accordingly; consumption deltas remain separate work before energy dashboards can be considered qualified.
2. **Blank page after a dashboard drill-down.** A link inside the HTMX refresh region changed the URL to the equipment page but left the page content blank. Navigation inside that region now uses full-page links; the device/site cards and attention actions load their destinations.
3. **False all-clear language.** No monitoring rule is active for this newly onboarded cold room. Command Center now shows an actionable "Alert monitoring not set up" notice, and Alerts states that monitoring is not configured rather than asserting that all devices are within configured limits. Delayed devices now appear in Needs Attention. The customer still needs to review and enable appropriate thresholds and notification recipients.
4. **Inert device status filters and confusing directory data.** The Devices directory had buttons that did not filter. Live, Delayed, Offline and Alarm are now working status links with a clear empty result. The page no longer describes all equipment as energy assets or shows an irrelevant energy category for the cold-room sensor. Last-reading timestamps now show site-local time and its zone.
5. **Small customization trap.** "Add panels" previously opened an empty drawer when all panels were visible. The action now disables with an explanation until a panel is hidden; hide, restore and cancel were exercised without saving any layout change.

### Telemetry chain and reliability evidence

At **17:59:14 Asia/Singapore**, a read-only Modbus TCP request on the CM4 to Laptop 2 (`10.0.0.20:502`, slave 1) returned **2.2200000286 °C, 72.7600021% humidity, door closed, compressor on**. The Hub's four stored readings from **17:59:13.391** were **2.22 °C, 72.760002%, false, true**. The source and Hub values match to display precision within one poll. The configured path is Laptop 2 → CM4 → authenticated MQTT broker → Hub consumer → TimescaleDB; this comparison verifies the endpoints, while no packet capture was taken at the broker. The dashboard trend's 17:59 hourly point displayed **2.81 °C**; a direct database average of the 89 numeric temperature samples in that hour was **2.8140 °C**.

The path is **intermittent**. Earlier the CM4 service and Gateway heartbeat stayed online while TCP `10.0.0.20:502` timed out and field telemetry aged out. Later the browser showed a gap from **18:04:23 to 18:15:33** (11 minutes 10 seconds) before live readings resumed. On a later revisit at about **23:45**, the Gateway heartbeat was still online but the device's last sample was at **18:20** (about five hours old). The customer UI correctly changed to Offline and had recovered to Live during the earlier interval. These observations do not establish a stable simulator link. The release test still needs a sustained run with dropout counts, polling errors, reconnect time, and source/Hub sample comparison across normal and interrupted periods.

A separate on-demand read is **not working on the installed CM4 version**. Clicking **Check all readings** now submits only the saved mapped signal keys and records the requests, but the Gateway returns failures. While the field path was down, the Gateway reported the device was absent from its registry. After live telemetry returned, all four checks failed with `expected string or bytes-like object, got 'dict'`. Code inspection traced this to the Gateway Modbus RPC parser: `read_device` built a `get` request with a dictionary of parameters, while the reserved `get` parser applies a regular expression to a string. A focused Gateway source fix on branch `fix/read-device-modbus-rpc` now emits the connector's documented string schema for Modbus reads, including bit reads; all 173 Gateway tests passed. **The CM4 was not upgraded and a physical on-demand read has not passed**, so this remains a release blocker. The Hub UI now says confirmation is unavailable and directs the operator to a local check rather than silently showing a generic failure.
